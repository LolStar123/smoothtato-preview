# Smoothtato visual editor

## Audience and job

A Path of Exile player configures graphics removals and cosmetic replacements. Both workspaces share the same product shell and current profile; either can export the complete supported configuration.

## Design references and signature

The internal references are the exported 68 settings/five presets and the actual 1,489-record catalogue with 1,107 preview icons. Graphics uses an editable CSS encounter sketch to illustrate retained effect groups. Cosmetics uses the real catalogue artwork to support selection. The scene never presents measured FPS, game footage or a precise rendering of all source categories.

Graphics uses a 1040 px frame, an encounter/preset split and a two-column switch list. Mobile stacks the workbench, keeps presets in a two-column group, and defaults to active changes. Cosmetics uses a 1120 px frame with a four-column catalogue and a 285 px inspection rail. At 850 px and below it shows eight compact icon/name/skill rows per page, with pagination at both ends; desktop shows 24 entries.

Tabs, controls and the profile summary connect the two workspaces. Counts identify source settings or selected effects, never a performance estimate. Preset button counts describe source changes; the redundant large changes counter has been removed. The header names Path of Exile on the first screen.

## Interaction and integrity

Original comparison changes only the illustration; it does not overwrite selections. Hidden animated groups have animation disabled, so keyframes cannot make removed effects reappear. Reduced motion disables all decorative CSS animation.

Switch rendering retains keyboard focus. Mobile effect selection focuses its heading, and returning to the list focuses the selected row. Page changes focus the result count. Broken/unavailable settings stay labelled, disabled and readable.

Both pages use `profile.mjs` and the real STATO1 field order. Import validation precedes storage writes; unknown/unmapped effects, multiple choices for a skill, conflicts, corrupt codes and unsupported extra fields retain the current configuration. Restoring graphics keeps cosmetics. Browser-local storage is not account sync. Failure to load either required dataset keeps actions disabled and gives a reload instruction.

## Shared implementation rules

Fonts come from the operating system; no font files or external requests are bundled. Layout starts from the working product, with no marketing cards, decorative gradients, scroll reveals or invented statistics. Code-native artwork stays editable. Controls use at least 44 px hit areas where practical and a visible two-pixel keyboard outline. Reduced motion disables decorative animation; essential state changes still happen.

Local acceptance: 1280 ? 1000 desktop and 390 ? 844 mobile, no horizontal page overflow, main flow and export, keyboard focus, unavailable/error states, and no uncaught page errors. README previews and ignored `output/qa/` screenshots are generated by the actual browser audits. Screenshots were visually inspected; the review is a solo craft check, not user testing.
